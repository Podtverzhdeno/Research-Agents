## Тезис
Если агенты компаний создают обязательства, банку выгодно стоять **в точке финансовой ответственности**: кредит / гарантия / управление рыночным риском / условный расчёт. Агент — уполномоченный исполнитель, не самостоятельное юридическое лицо. Вероятностная модель не должна напрямую решать вопрос окончательности платежа.

## Принцип распределения по конкретным ФБС

- **3.1.9 Управление полномочиями клиента:** многошаговый мандат с ограничениями суммы, контрагента, срока, риска и отзывом всей цепочки агентов. **Основа**, не отдельный кредитный продукт.
- **3.1.15 Идентификация агента:** связка юрлицо → агент → экземпляр → ключ → версия. **Основа**, не правосубъектность агента.
- **3.3.3 Поддержка продаж:** машиночитаемые оферты по A1–A4 для внешних агентов; машина сравнивает полную стоимость. **Канал монетизации**, не пятый продукт.
- **4.1.1 Управление распоряжениями:** агентское намерение конвертируется в допустимое банковское распоряжение только после проверки мандата.
- **4.1.2 Управление договорами:** правила банка по гарантии, кредиту и эскроу, юридически значимая связь с внешним основанием.
- **4.1.4 Счета:** сублимит бюджета агента на счёте юрлица; не «счёт ИИ».
- **4.1.5 Комиссии:** цена за гарантию, эскроу, финансирование и SLA; не предполагаем априори оплату за API.
- **4.1.6 Депозиты:** размещение свободных остатков по казначейскому мандату — **поддержка A4**.
- **4.1.10.1 / 4.1.10.2:** расчёты, финальность, маршрутизация и идемпотентность; переговоры/«корзина» не являются банковским расчётом.
- **4.1.11 Обеспечения:** поэтапное освобождение согласованного обеспечения при подтверждении результата — **поддержка A1/A2**.
- **4.1.14.2 Эмиссия финансовых инструментов:** **не** является общим факторингом; не подменять A1.
- **4.1.14.4 Сделки с финансовыми инструментами:** только разрешённые клиентом сделки, хедж и лимиты — **поддержка A4**.
- **5.4.1 Управление предоставлением сервисов платформы:** A2A/MCP-шлюз с мандатами, маршрутами, аудитом — инфраструктура, не финальный банк-продукт.
- **5.2.6 Управление мониторингом:** аномальные массовые действия, остановка операций, корреляция ущерба.
- **6.1.5 / 6.1.6 / 6.1.11:** граф сделки, события от ERP/ЭДО/логистики, интероперабельность — **факт не равен независимому доказательству**.
- **7.5.1 AML Контроли:** выявление коалиций агентов, кольцевых операций, обхода мандатов; безопасность банка, не отдельная клиентская продажа.
- **7.7.2.1.3.2 Управление криптографическими активами:** ключи/сертификаты/ротация; **не** криптовалютный кошелёк.
- **7.2.2.3 Учет ДЗ/КЗ:** учёт ДЗ/КЗ **банка**, не клиентский факторинг.
- **4.1.13.1 Управление наличной ликвидностью:** физическая наличность, **не** корпоративный FX.
- **3.8 Обработка обращений:** претензии клиенту к банковскому сервису, handoff; независимый коммерческий арбитраж между юридическими лицами требует отдельного правового основания.

## Недоказанные предпосылки / условия отказа

1. Заказ/поставка достоверно и **независимо** подтверждены; при споре есть альтернативный канал приёмки.
2. Банк имеет законные права на данные и доказательства, а кредитор — действительное право требования.
3. Цена продукта покрывает кредитный риск, операционные потери, стоимость данных, разбирательств и интеграции.
4. Указанные гарантии допускают согласованный порядок изменения и выплаты, нельзя односторонне «перемерять гарантию».
5. Есть достаточно клиентов и встречных обязательств для неттинга X1; при недостаточном масштабе X1 отклоняется.
6. Не допускать FX/кредитных решений LLM без детерминированных лимитов, санкционных, AML и риск-проверок.
7. Клиент может иметь агента и без единого стандарта: не привязывать монетизацию к единственному протоколу.
