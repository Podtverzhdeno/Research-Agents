# Закрытие всех 26 предметных споров — прикладные ФБС банка

**Редакционное решение 29 октября 2026.** Коды и названия сверялись с пользовательским реестром из 639 строк; здесь только аналитические решения, **без буквальных внутренних определений**. Исходные исторические 40 «Доработка» / 3 «Новая» / 11 «Без изменений» не изменяются.

**Разрешено по смыслу: 26/26.** Для 25 подтверждена непротиворечивая граница существующей ФБС; для 3.1.15 определён функциональный fallback, но **официальный номер не подтверждён**. Исследовательский консенсус является аналитической позицией GPT-6, а не подписью реальных владельцев банка.

## Обязательные для решения запреты

1. Нет автоматического выпуска гарантии или кредита потому, что клиентский агент прислал документы: risk/право/договор отвечают по отдельным правилам.
2. Нет автоматического release escrow от произвольного статуса ERP. ГК РФ 860.7 — основание выплаты предусматривается договором счёта эскроу.
3. Нет автоматического изменения независимой гарантии по одному акту поставщика: гарант, принципал, бенефициар и основания определяются условиями инструмента (ГК РФ 368, 370, 371).
4. Нет отдельной личности-заёмщика, счёта или юридической подписи ИИ-агента, возникшей из токена.
5. Данные, граф, подпись и криптохэш не дают сами по себе право требования или доказательство реального исполнения.
6. Нет обещания внешнего платежа без поддержки внешнего банка и мандата; допустима read-only деградация.
7. Нет приписывания банковскому эмитенту карты эквайринга платежа торговцу без соответствующей роли.

| `3.1.9` | Проверить единый атомарный предел полномочий нескольких агентов; счёт и фактическое списание отдельно. |
| `3.1.15` | НЕ утверждать как действующий код ФБС: отсутствует в предоставленном реестре. Проектно покрыть 3.1.7.1 + 3.1.2 + 3.1.9 + 2.2 + 7.7.2.1.3.2; вопрос каталога остаётся у его владельца. |

## Восемь бизнес-CJM и две разные гарантии

| Сценарий | Какие реальные участники и кто действует | Негативный тест, закрывающий спор |
|---|---|
| Гарантия **исполнения** | Принципал — поставщик; бенефициар — покупатель; банк гарант — 4.1.22.2 | Неверный бенефициар/истёкший мандат → выпуск не производится |
| Гарантия **оплаты** | Принципал — покупатель; бенефициар — поставщик; банк гарант — 4.1.22.2 | Подмена должника или условий → риск и продукт пересматривают заявку |
| Эскроу по приёмке | 6.1.6 собирает акт, 6.1.7 отмечает конфликт, 4.1.24 проверяет договорное условие | Два противоречивых акта не дают права на автоматическое перечисление |
| Внешние счета клиента | 4.1.12 предоставляет поддерживаемые сведения/функции чужого банка при законном основании | Отзыв прав/отсутствие внешнего API → нет операции, read-only или отказ |
| Общий бюджет агентов | 3.1.9 управляет единым полномочием, 4.1.4 и расчётные ФБС работают с деньгами | 10 одновременных заявок и отзыв не превышают общий лимит |
| Корпоративная карта | 4.1.8.1 — выпуск; 4.1.9.3 — сторона приёма, только если наш банк эквайер | Недоступная схема/повторный capture/не тот мерчант не проводят лишний платёж |
| Минимальное подтверждение оплаты | 3.1.10 основание; 6.1.5 сведения; 6.1.10 законная передача | Чужой получатель не увидит даже агрегат без права |
| Покупка финансового инструмента | 4.1.1 — поручение; 4.1.14.4 — поддерживаемая сделка | Простой платёж поставщику не попадает в эту ФБС |
| Жалоба на банковский канал | 3.8 — банковское обращение; 3.5 — история | Жалоба о некачественном товаре не превращается в банковский коммерческий арбитраж |

## Решение по единственному источниковому расхождению: 3.1.15

**Не «ждём» и не придумываем каталог:** используем существующую функцию 3.1.7.1 для учёта агента у клиента, 3.1.2 для аутентификации клиентской сессии, 3.1.9 для делегирования, 2.2 для доступа и 7.7.2.1.3.2 для ключей. Новый выделенный код 3.1.15 пока остаётся **проектным предложением**, не официальным паспортом. Проверка владельцем справочника нужна только для создания/номенклатуры ФБС, **не блокирует описанный защищённый CJM**.
