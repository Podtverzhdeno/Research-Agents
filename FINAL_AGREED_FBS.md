# FINAL_AGREED_FBS.md — идеи, по которым совпали опубликованные позиции агентов

**Дата:** 28.10.2026 · **Горизонт:** 2031–2036 · **Статус:** `AGREED_WITH_CONDITIONS` в пределах опубликованных исследовательских позиций GPT-6, **не** юридическая/экономическая приёмка банка.

**Основание:** явные голоса в [Issue #21](https://github.com/Podtverzhdeno/Research-Agents/issues/21) от `gpt6-strategy` и `gpt6-critical-review`, повторные проверки `finance-challenge` и `PEER_REVIEW`. Все эти проходы выполнены моделью GPT-6 — **не представлять их независимым одобрением разных моделей/экспертов**.

## 1. Совместно поддержанное продуктовое ядро — кратко по ФБС

| Приоритет | ФБС | Уточнённая идея (для исходной карты) | Зачем клиенту / банку | Согласование |
|---|---|---|---|---|
| **P1** | **Кредитование / факторинг — ВНЕ фрагмента 54, код не известен** | Финансирование многоуровневого B2B-заказа по проверенному требованию с погашением из поступлений. | Поставщику — оборотный капитал; банку — проценты/факторинговая комиссия | **AGREE_WITH_CONDITIONS** |
| **P2** | **4.1.22.2 Гарантии** | Гарантия исполнения агентной сделки с заранее согласованными условиями этапного покрытия. | Заказчику — защита; банку — гарантийная комиссия | **AGREE_WITH_CONDITIONS** |
| **P3** | **4.1.24 Эскроу** | Поэтапный расчёт по независимой приёмке с частичным удержанием и процедурой спора. | Обеим сторонам — меньше риска; банку — комиссия и расчётный поток | **AGREE_WITH_CONDITIONS** |

**Главная собранная клиентская идея:** заранее одобренная **покупательная способность юридического лица**, доступная его агентам **на конкретные проверенные B2B-обязательства**. Финансирование, гарантия и эскроу остаются юридически разными продуктами и ФБС, объединёнными в одном клиентском пути.

**Критическая граница:** техническая подпись или подтверждение ERP **не доказывают реальную поставку**. Контроль должен включать независимые источники и порядок спора; LLM не является финальным авторизатором расчёта.

## 3. Где согласовано НЕ добавлять отдельную «новую» ставку

| Идея | Совместный вывод | ФБС |
|---|---|---|
| **A4 Автономное казначейство/FX** | `REVISE / EMBEDDED_ADD_ON`: только cross-sell внутри P1–P3 до доказанной дополнительной ценности | 4.1.6, 4.1.14.4; основная FX/безналичная ликвидность **вне 54** |
| **X1 Сетевой многосторонний зачёт** | `RESEARCH_ONLY`: нет проверенной юридической схемы, финальности и достаточной сети клиентов | 4.1.10.1–2 только расчёты; клиринг/зачёт **вне 54** |
| **KYA, агентный кошелёк, MCP/A2A gateway** | Нужная инфраструктура; не новый самостоятельный банковский продукт | 3.1.15, 4.1.12, 5.4.1 |
| **«Финансовый паспорт сделки»** | Фундамент данных для банка; отдельно не доказана монетизация | 6.1.5, 6.1.6, 6.1.11 |
| **Арбитраж как решение LLM** | Не предлагать: процедура спора должна соответствовать договору/праву | 3.8, 4.1.24 |

## 4. Блокирующие условия, которые не прошли проверку до статуса APPROVED

- Действительность требования, предотвращение двойного финансирования и доказательство реального исполнения (P1).
- Юридически допустимые условия изменения/исполнения гарантии с соблюдением прав бенефициара (P2).
- Независимая приёмка, конфликт доказательств, ответственность за ложный триггер, частичный возврат (P3).
- Сравнительная `risk-adjusted` маржа с обычными SCF/гарантией/эскроу; данных о платёжной готовности нет.
- Полный утверждённый справочник ФБС банка и позиции владельцев процессов; коды за пределами 54 не придумывать.
- Режим использования внутренних банковских материалов в **публичном** репозитории — проверить и при необходимости перевести в private.
