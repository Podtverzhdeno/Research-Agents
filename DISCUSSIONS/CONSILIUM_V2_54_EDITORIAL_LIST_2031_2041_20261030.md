**A / baseline:** Обычная публикация API утверждённого банковского продукта в существующем канале. **B / 2031–2036:** Агент банка обнаруживает несовместимость полей заявки гарантии с уже действующим ERP-каналом, предлагает совместимый пакет подключения и проводит семантические contract tests. **C / 2036–2041:** При изменении потребностей группы корпоративных агентов сам подбирает из утверждённого банка каталога конфигурацию услуги для того же канала, выкатывает только после policy gate. **D / NO BET:** Если SDK и конфигурационный адаптер дают тот же результат дешевле — отказаться от агентной ставки.

**Результат именно этой ФБС:** Доступность конкретного утверждённого банковского продукта в существующем канале, не новое банковское предложение. **Тест-убийца:** Поменять местами принципала и бенефициара при валидной JSON-схеме: публикация должна быть заблокирована. **Метрика ценности:** Время/стоимость безопасного подключения продукта к существующему каналу.

**Результат именно этой ФБС:** Проверенная настройка электронной части существующего канала и переходов, а не банковский продукт. **Тест-убийца:** При потере ответа агент повторяет пять раз: один case ID, без пяти заявок. **Метрика ценности:** Доля успешных переходов между каналами без повторного ввода.

**Результат именно этой ФБС:** Решение AML по банковской операции/сигналу, не управление кредитным риском. **Тест-убийца:** Тысячи субагентов дробят выплаты между юрлицами: сценарий не исчезает за новыми agent ID. **Метрика ценности:** Recall/precision AML и регуляторный риск.

### 52. `7.6.2` — Управление взаимоотношениями с внешними контролирующими органами

**Исходный статус:** Доработка · **V2-решение:** `E` — ДОРАБОТКА СУЩЕСТВУЮЩЕЙ ФБС (кандидат)

**A / baseline:** Стандартное взаимодействие банка с регулятором по запросам. **B / 2031–2036:** Собирать проверяемый след решений agent→mandate→bank effect для законного отчёта. **C / 2036–2041:** Формировать многослойное объяснение по цепочке автономных банковских решений с раскрытием только требуемых регулятором данных. **D / NO BET:** Если обычная регуляторная отчётность уже полна, не делать отдельную AI-функцию.

**Результат именно этой ФБС:** Корректный ответ/отчёт для внешнего контролирующего органа по установленным правилам. **Тест-убийца:** Запрос от сомнительного внешнего «надзора» не раскрывает банковскую тайну. **Метрика ценности:** Полнота и срок ответа на законные запросы.

### 53. `7.7.2.1.3.2` — Управление криптографическими активами

**Исходный статус:** Новая · **V2-решение:** `P` — УЖЕ ПРЕДУСМОТРЕНА КАК «НОВАЯ» В ИСХОДНЫХ 54; подтвердить каталог

**A / baseline:** Учёт/хранение стандартных криптографических активов и сертификатов. **B / 2031–2036:** Аттестовать и отзывать ключи конкретного runtime/версии агента с журналом операций. **C / 2036–2041:** Выпускать эпизодические доказуемые credentials под отдельные разрешённые банковские операции с коротким сроком и отзывом цепочек. **D / NO BET:** Не создавать новую вторую ФБС для agent credentials, пока проектная 7.7.2.1.3.2 покрывает криптографический объект.

**Результат именно этой ФБС:** Действующие криптографические ключи/сертификаты, не клиентский юридический мандат. **Тест-убийца:** Ключ скомпрометирован до использования мандата — отзыв должен мгновенно остановить новое исполнение. **Метрика ценности:** Время отзыва, число несанкционированных криптографических действий.

### 54. `7.11.1` — Создание и подписание документов

**Исходный статус:** Доработка · **V2-решение:** `E` — ДОРАБОТКА СУЩЕСТВУЮЩЕЙ ФБС (кандидат)

**A / baseline:** Обычное создание и подписание банковских документов. **B / 2031–2036:** Подготовить подписываемый документ из разрешённой банковской операции и зафиксировать полномочие. **C / 2036–2041:** Составной документальный процесс agent→reviewer→authorized signatory с машинной проверкой неизменности смысловых условий и подписей. **D / NO BET:** Если обычный СЭД/ЭП реализует тот же контроль, не нужен новый signature-agent.

**Результат именно этой ФБС:** Законно созданный и подписанный документ, не самостоятельное право агента. **Тест-убийца:** Подмена суммы/бенефициара между согласованием и подписью блокируется. **Метрика ценности:** Доля недействительных документов и время согласования.
