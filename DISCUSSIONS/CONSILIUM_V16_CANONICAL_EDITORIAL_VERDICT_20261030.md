## Краткий ответ: какие новые ФБС должны появиться?

1. **Сверить и оформить проектную `3.1.15` — Идентификация агента.** Она уже присутствует в проектной функциональной карте как новая; в прежнем полном реестре код не найден. Предмет — проверяемые юридическое лицо, идентичность работающего агента, версия, runtime, криптографический ключ и отзыв. Не заменяет `3.1.9` (полномочия) и `2.2` (доступ к каналу). Статус **VERIFY_PROJECT_NEW**, не принятая банком новая запись.
2. **N1 — согласованность связанных собственных обязательств банка:** **не создавать сейчас**. Альтернатива `4.1.2 + 4.1.11 + 4.1.22.2 + 4.1.24 + 4.1.10.* + 5.6.2 + BPM/saga`. Новый код только если банк докажет самостоятельное договорное обязательство, владельца, спрос, положительную риск-скорректированную экономику и отсутствие дублирования.
3. **N2 — договорная независимая оценка доказательств исполнения:** **не создавать сейчас**. Альтернатива `6.1.6/7/11 + 7.7.2.1.1.4 + 4.1.24 + независимый инспектор`; две подписи подконтрольных одному бенефициару агентов не доказывают поставку. Новый код только при отдельной юридической ответственности и платящей клиентской группе.
4. **Другие общие новые функции** agent runtime, orchestration, memory, security/audit, model risk и AML **не плодить**, так как по доступному полному каталогу уже существуют `5.6.1–5.6.3`, `7.13.6`, `7.1.14`, `7.12.4`, `7.5.1` и смежные владельцы.

**Ответ:** подтверждённых *дополнительно необходимых* новых кодов **0**. Имеется **1 проектная к оформлению** и **2 HOLD-кандидатуры**, но только после полного GAP по каталогу.

## Какие ФБС можно оставить без обязательной специальной агентной доработки?

**Семь `NO_BET`** — отдельная предметная агентная ставка не обоснована, хотя штатная автоматизация возможна. **Ещё три `NO_PASSPORT_CHANGE`** — назначение ФБС прежнее, но специализированные ИТ, восстановление и бухгалтерские правила **могут потребовать работы**. Не смешивать эти категории.

| Код | ФБС | Статус | Сильнейшее возражение / условие пересмотра |
|---|---|---|---|
| `4.1.13.1` | Управление наличной ликвидностью | `NO_BET` | Если конкретный клиентский кейс меняет физический поток, допустим обычный прогноз без изменения ФБС. |
| `4.1.13.2` | Инкассация | `NO_BET` | Если автоматизация заявки не улучшает логистику, оставить процесс как есть. |
| `4.1.13.3` | Самоинкассация | `NO_BET` | Нет потребности изменять паспорт ФБС при обычной интеграции терминала. |
| `4.1.13.4` | Кассовое обслуживание клиентов | `NO_BET` | Если нет новой законной категории получателей/операций, NO BET. |
| `4.1.13.5` | Экспертиза и инкассо наличных денежных средств и ценностей | `NO_BET` | Без нового физического метода проверки отдельная агентная ФБС не нужна. |
| `5.3.2` | Создание технологической инфраструктуры | `NO_PASSPORT_CHANGE` | Новый рантайм может потребовать infra-work, но это не новая бизнес-способность |

| `7.2.2.1.2` | Отражение операций в бухгалтерском учете | `NO_PASSPORT_CHANGE` | Новые ЦФА могут потребовать новых проводок, но не новой функции отражения учёта |

## Что сделало этот отбор более строгим

- **Не записываем в будущее уже применяемое в 2026.** Visa/BILL/Billtrust 20.10.2026 сообщили о live pilot **исполнения ранее одобренных** B2B-инвойсов доверенными агентами. NIST 27.10.2026 сформулировал design tenets agent identity, signed mandates, делегирования, deterministic access, revocation. Это стартовая линия, не наше изобретение: https://investor.visa.com/news/news-details/2026/Visa-BILL-and-Billtrust-Launch-First-Live-Pilot-for-Trusted-AI-Agent-Payments-Between-Buyer-and-Supplier-Platforms/default.aspx ; https://www.nist.gov/blogs/cybersecurity-insights/design-tenets-agent-identity-management-systems .
- **Не путаем типы ликвидности.** BIS Project Agenti (14.10.2026) изучает wholesale intraday liquidity, а `4.1.13.1` из нашей 54-карты — физические банкноты: https://www.bis.org/node/87745 .
- **Не объявляем цифровую семантику новой сама по себе.** ICC Digital Standards Initiative (02.10.2026) уже расширяет работу по trade-record interoperability. Ценность `6.1.11` — детерминированное доказательство несмешения «отгружено/доставлено/принято» в банковской операции: https://iccwbo.org/news-publications/news/icc-digital-standards-initiative-announces-next-phase-of-operations/ .
- **Не притягиваем соседние ФБС.** Deep-tier факторинг/кредитование, полноценный FX/treasury и межфирменный netting/clearing по исходному набору требуют отдельных реальных владельцев вне 54; поддержку из `6.1.*` или расчёты `4.1.10.*` не выдавать за кредитный продукт.
