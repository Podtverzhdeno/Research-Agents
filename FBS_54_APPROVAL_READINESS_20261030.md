## Решение по двум вопросам

**Новые ФБС:** функциональный проект предлагает `3.1.15` идентификация агента; согласовать её версию с полным каталогом. H1 «согласованность связанных **собственных банковских** обязательств» — главная исследовательская кандидатура (сравнить с `4.1.2 + 5.6.2` и продуктами). H2 «договорное банковское удостоверение исполнения» — слабее; не утверждать отдельный код без независимой юридически ответственной услуги с клиентом и экономикой. Generic agent eval, access, A2A, AML и банковские оферты не дублировать новыми кодами при наличии существующих способностей.

**Без специальной агентной доработки:** `4.1.13.5`, `7.2.2.3`, `7.2.7.3`; ядро `4.1.13.3`, `4.1.13.4` сохраняется при возможных ИТ/процессных изменениях. `4.1.13.6.2` остаётся scope HOLD из-за цифровых активов.

## Независимые критерии одобрения каждой строки

- `OWNER`: утверждённый паспорт и подпись фактического владельца ФБС + ссылка на документ.
- `PRODUCT`: получатель ценности, лучший текущий baseline, эффект после cost-to-serve и риска + ссылка.
- `LEGAL`: правильный субъект, действительное обязательство, полномочия и отсутствие ложной финальности + ссылка.
- `RISK/INFOSEC`: collusion, spoofing, revocation, replay, двойной платёж/выдача, cap limits + ссылка.
- `QA/E2E`: запущенный отрицательный тест, дата, версия и журнал исполнения + ссылка.
- `CONSILIUM`: **каждая ФБС отдельно** имеет server-proven >=3600 wall seconds **и** >=3600 seconds verified active discussion с checkpoint 15 минут, все реальные agent IDs, нет имитации активности; rule [time gate](https://github.com/Podtverzhdeno/Research-Agents/blob/main/CONSILIUM_SESSION_TIME_GATE.md).
- `SCOPE`: конфликты кода/определения `3.1.15`, `4.1.1`, `4.1.14.2`, `4.1.13.6.2` разрешены уполномоченным владельцем каталога.

Все вышеуказанные условия должны быть выполнены; **нельзя считать редакционный выбор банковским approval**. Приватная полная таблица с дословными определениями и редактируемым 54-строчным листом согласования передана в чат, **в GitHub не публикуется**.
